# Segurança

O NutriDB distribui dados e ferramentas de build. Não deve ser tratado como
uma API clínica, nem como fonte de aconselhamento médico.

## Reportar uma vulnerabilidade

Não publique detalhes exploráveis numa issue pública. Envie uma descrição para
`betuel801@gmail.com` com o assunto `NutriDB security report` ou use um canal
privado de Security Advisory do GitHub, quando disponível.

Inclua, se possível:

- versão, commit ou artefacto afetado;
- passos mínimos para reproduzir;
- impacto esperado e observado;
- logs sem segredos ou dados pessoais;
- sugestão de correção, se existir.

Não envie credenciais, tokens, dados pessoais ou dumps de fontes licenciadas.

## Integridade dos dados

Erros de proveniência, mappings, unidades, ausência ou licença também são
incidentes de integridade. Reporte-os de forma privada quando puderem afetar
consumidores antes de existir uma correção.
